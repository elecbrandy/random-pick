# Random Pick 웹사이트 설계

## 목적과 범위

알파벳과 숫자 한 쌍을 간단히 뽑는 공개 웹사이트를 만든다. 사용자는 한 화면에서 숫자 범위를 정하고 버튼 하나로 A~Z의 한 글자와 범위 안의 정수 하나를 동시에 추첨한다. 서버, 로그인, 결과 저장, 공유 기능은 이번 범위에 포함하지 않는다.

## 사용자 흐름

1. 처음 열면 알파벳 슬롯에는 `?`, 숫자 슬롯에는 `?`가 보이고 숫자 범위는 최솟값 `1`, 최댓값 `100`이다.
2. 사용자는 최솟값과 최댓값을 각각 입력할 수 있다. 두 값은 안전한 정수여야 하며 최솟값은 최댓값 이하이다. 0과 음수도 허용한다. 포함된 정수의 개수 `max - min + 1`도 안전한 정수 범위에 있어야 한다.
3. `뽑기` 버튼을 누르면 두 슬롯이 약 1.5초 동안 빠르게 다른 값을 보여준 후 함께 최종 결과에 멈춘다. 추첨 중에는 버튼을 다시 누를 수 없다. 버튼의 입력 시점에 유효했던 범위로 숫자를 뽑는다.
4. 입력이 비어 있거나 유효하지 않으면 추첨하지 않고 해당 입력 옆에 짧은 오류를 표시한다. 화면을 새로 열면 초기 상태로 돌아간다.

## 화면과 접근성

제목과 짧은 설명 아래에 두 결과를 같은 비중으로 배치한다. 데스크톱에서는 나란히, 좁은 화면에서는 세로로 쌓는다. 결과 글자는 크게, 입력과 버튼의 레이블과 포커스 상태는 명확하게 표시한다. 키보드로 모든 조작이 가능해야 한다. 오류와 최종 결과는 보조 기술이 읽을 수 있게 알린다. 사용자의 움직임 줄이기 설정이 활성화되면 슬롯 회전 없이 결과를 즉시 표시한다.

## 기술 설계

- Vite와 순수 TypeScript로 정적 사이트를 만든다. 별도 서버나 UI 프레임워크는 사용하지 않는다.
- 범위 파싱·검증과 결과 생성은 DOM 코드에서 분리한다. A~Z에서 한 글자와 입력된 닫힌 구간에서 정수 하나를 뽑는다. 난수 품질은 일반적인 뽑기 용도에 맞추며 보안 용도를 약속하지 않는다.
- 화면 상태는 초기, 입력 오류, 추첨 중, 결과 표시 네 가지로 관리한다. 추첨 중 범위 입력은 잠가 결과와 입력 값이 어긋나지 않게 한다.
- GitHub Actions가 기본 브랜치 변경 시 설치·검사·빌드 후 `dist`를 GitHub Pages에 배포한다. Vite의 `base`는 저장소 주소 `elecbrandy/random-pick`에 맞춰 `/random-pick/`로 설정한다. GitHub 저장소의 Pages 배포 소스는 GitHub Actions로 설정해야 한다.

## 검수 기준

- 기본 범위와 사용자가 바꾼 범위에서 두 결과가 올바른 집합에 속한다. 최솟값과 최댓값이 같은 경우 그 숫자만 나온다.
- 빈 값, 소수, 안전하지 않은 정수, 역전된 범위는 추첨을 막고 이해할 수 있는 오류를 보여준다.
- 연속 클릭으로 여러 애니메이션이 겹치지 않는다. 움직임 줄이기 설정에서는 즉시 결과가 표시된다.
- 키보드, 좁은 화면, 빌드 결과의 정적 경로를 확인한다. GitHub Pages 배포 워크플로의 성공과 실제 URL 접속 여부를 확인한다.
