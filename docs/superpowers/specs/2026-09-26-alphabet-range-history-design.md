# 알파벳 범위와 세션 추첨 기록 설계

## 목적

기존 랜덤 뽑기에 알파벳 범위 선택과 조합 기록을 추가한다. 같은 탭의 세션에서 확정된 알파벳·숫자 조합은 다시 최종 결과로 나오지 않는다. `A-1`이 나온 뒤에도 `A-2`와 `B-1`은 뽑을 수 있다.

## 입력과 추첨 규칙

- 알파벳 시작·끝은 A~Z 선택 목록으로 제공하며 기본값은 `A`~`Z`다. 두 끝을 포함하고 시작은 끝보다 앞서거나 같아야 한다.
- 숫자 최솟값·최댓값은 기존 규칙을 따른다. 기본값은 `1`~`100`; 안전한 정수와 안전한 범위 너비를 요구한다.
- 추첨 시점의 두 범위에 속하는 **아직 확정되지 않은 조합** 중 하나를 균등하게 선택한다. 과거에 다른 범위에서 뽑은 조합이라도 현재 범위에 속하면 제외한다. 범위를 바꿨다가 되돌려도 제외 상태는 유지된다.
- 큰 숫자 범위도 허용하므로 가능한 조합 전체를 메모리에 만들지 않는다. 현재 범위의 남은 조합이 0개이면 추첨을 막고 범위 변경을 안내한다.
- 슬롯 회전 중 표시되는 값은 시각적 효과일 뿐이다. 약 1.5초 뒤 확정된 한 조합만 기록하고 중복 금지 대상으로 삼는다. 움직임 줄이기 설정에서는 바로 확정한다. 회전 중 다른 추첨이나 범위 변경은 허용하지 않는다.

## 기록과 세션

- 기록은 `알파벳 · 숫자` 조합을 최신순 목록으로 모두 보여주고 총 개수를 표시한다. 결과가 없으면 빈 상태 안내를 보여준다. 기록 영역은 길어지면 자체 스크롤한다.
- `sessionStorage`에 확정된 결과를 순서대로 저장한다. 같은 탭에서 새로고침하면 기록과 중복 금지 상태를 복원한다. 범위 입력은 새로고침 시 기본값으로 돌아가고, 두 결과 슬롯에는 마지막 확정 결과를 보여준다. 탭을 닫으면 세션은 종료된다.
- 저장된 값이 손상되었으면 유효한 A~Z·안전한 정수의 고유 조합만 복원한다. `sessionStorage`에 접근하거나 저장할 수 없는 경우 열린 페이지에서는 메모리 기록을 유지하고, 새로고침 후 유지되지 않을 수 있음을 화면에 알린다.
- 이번 범위에는 기록 초기화 버튼, 서버 동기화, 다른 탭 간 기록 공유를 포함하지 않는다.

## 화면과 접근성

기존 두 슬롯 아래에 알파벳 범위 선택 두 개와 숫자 범위 입력 두 개를 명확한 레이블로 배치한다. 데스크톱과 좁은 화면 모두 한 번에 읽기 쉬운 순서를 유지한다. 잘못된 범위와 소진 상태는 입력 가까이 표시하고 보조 기술에도 알린다. 추첨 완료 시 최종 조합을 한 번 알리고 기록 목록을 갱신한다. 회전 중 보이는 임시 값은 별도 실시간 알림을 만들지 않는다.

## 구현 경계와 검수

- `src/picker.ts`는 범위 검증과 남은 조합에서 편향 없이 하나를 선택하는 순수 로직을 맡는다. 조합 수는 안전한 숫자 범위보다 클 수 있어 `bigint`로 계산한다.
- `src/history.ts`는 세션 기록의 로드·저장과 손상 데이터 정리를 맡는다. DOM과 저장소 예외를 추첨 로직에서 분리한다.
- `src/app.ts`는 입력, 슬롯 상태, 기록 화면을 연결한다. 기존 GitHub Pages 배포 경로는 유지한다.
- 경계 범위, 조합 중복 방지, 변경된 범위와 소진 상태, 기록 순서, 새로고침 복원, 손상 데이터, 저장소 오류, 움직임 줄이기를 테스트한다. 타입 검사, 전체 테스트, 빌드를 통과해야 한다.
